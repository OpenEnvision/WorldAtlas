# Perceptual Quality

`perceptual_quality` 用来衡量预测结果自身的视觉质量，不和参考结果做比较。

## 这个指标测什么

- 帧级锐度、干净程度和审美合理性
- 锚点帧层面的图像质量，而不是语义正确性
- 完全不依赖参考图像或参考视频

## 具体算法

1. WorldArena 只对预测锚点帧打分。
2. reference runtime 会加载两个 IQA 组件：
    - `clipiqa+`
    - `laion_aes`
3. 对每个锚点帧 `f_i`，两个组件分别输出原始分数：
    - `clipiqa+` 按 `1.0` 缩放
    - `laion_aes` 按 `10.0` 缩放
4. 每个组件都被转换为有界分数：`component_score = clamp(native / scale, 0, 1)`。
5. 帧分数是这些必需组件分数的算术平均。
6. 原始指标值为 `raw = mean_i frame_score_i`。
7. 由于当前配置本来就期望 `[0, 1]`，benchmark 归一化实际上是恒等映射。

## 输入与输出

| 项目 | 当前实现 |
| --- | --- |
| 预测输入 | 预测锚点帧 |
| 参考输入 | 无 |
| 标注输入 | 无 |
| 原始输出 | `[0, 1]` 上的单个标量平均帧质量分数 |
| 归一化输出 | 同一个 `[0, 1]` 标量 |
| 细节字段 | `frame_scores`、`required_components`，以及每个组件的原始与归一化分数 |
| 失败形式 | 如果任一必需 IQA 组件不可用，则返回 `raw = null`、`normalized = null` 和错误字符串 |

## 当前集成是否足够严格

| 项目 | 结论 |
| --- | --- |
| 当前聚合状态 | 只要产出数值分数，就是 `official` |
| 论文可用性结论 | `主表可用` |

- 相对更强的原因：算法在仓内实现，组件堆栈明确，聚合逻辑直接。
- 仍然不能单独下结论的原因：它并不知道内容对不对。一个漂亮但语义错误的样本也可能得高分。
- 建议用法：可以作为主表里的感知质量维度，但必须和语义、控制类指标一起报告。
