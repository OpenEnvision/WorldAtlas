Physics Metrics & Contracts

All simulator-backed metrics in config/benchmark_physics.yaml currently resolve to the simulator_reference backend. The benchmark runner computes that backend once per sample and caches the result, so enabling more than one physics metric does not rerun the external evaluator for the same prediction file.

For reporting purposes, configured and optional simulator-backed metrics in the physics track, plus the judge metrics in config/benchmark_physics_judge.yaml, all belong to the top-level physics dimension.

Simulator Based Physics Evaluation Metric Groups

Section titled “Simulator Based Physics Evaluation Metric Groups”

physics_spec.metrics_design groups required simulator-backed metrics into five core groups, plus a scenario-conditional final-state group. Each group’s detailed inputs, computation semantics, score direction, and failure behavior live on a dedicated page:

simulator-backed groupMetricsDetail page
video_physicsmse, st_iou, s_iou, ws_iouVideo Physics
geometry_3dabs_rel, rmse, delta1, delta2, delta3Geometry 3D
temporal_consistencydepth_warp_l1, depth_warp_charb, rgb_warp_charb, epe, fl_all, one_px_out, plus optional rgb_warp_lpipsTemporal Consistency
world_4dchamfer_4d, worldline_l2_error, worldline_mean_drift, worldline_final_drift, worldline_fail_rate, worldline_length, plus optional novel_time_*World 4D

final_stateoptional final_state_accuracy when the sample declares a final-state rule or labelsFinal State

These groups flatten into the current required_core_metrics contract carried inside each physics sample. Custom configs that enable optional metrics should also declare matching backend and normalization entries.

Normalization Map

Section titled “Normalization Map”

The current config declares the following normalization ranges. See the group pages above for per-metric explanations.

WorldArena’s generic normalization formula is:

norm(x)={clip[0,1](x−lu−l),higher_is_better=trueclip[0,1](u−xu−l),higher_is_better=false\mathrm{norm}(x)= \begin{cases} \mathrm{clip}_{[0,1]}\left(\dfrac{x-l}{u-l}\right), & \text{higher\_is\_better=true}\\[8pt] \mathrm{clip}_{[0,1]}\left(\dfrac{u-x}{u-l}\right), & \text{higher\_is\_better=false} \end{cases}norm(x)=⎩⎨⎧​clip[0,1]​(u−lx−l​),clip[0,1]​(u−lu−x​),​higher_is_better=truehigher_is_better=false​

where xxx is the raw metric, lll is lower, and uuu is upper. If u≈lu\approx lu≈l, the implementation directly clips the raw value into [0,1][0,1][0,1].

Artifact Contract

Section titled “Artifact Contract”

Physics evaluation distinguishes between local ground-truth exports and predicted world exports.

world_gt/

Section titled “world_gt/”
Contract levelFiles
minimum video readinessrgb.mp4
full core-metric readinessrgb.mp4, depth.npz, flow.npz, mask.npz, occlusion.npz, cameras.npz, points4d.npz, worldlines.npz
optional extrasnovel_time_depth.npz, novel_time_rgb.npz, rgb_frames/, export_info.json

pred_world/

Section titled “pred_world/”
Contract levelFiles
required for the current core contractdepth.npz, mask.npz, flow.npz, cameras.npz
optional extrasocclusion.npz, points4d.npz, worldlines.npz, novel_time_depth.npz, novel_time_rgb.npz

For trajectory_dynamics, WorldArena will reuse pred_world/worldlines.npz when present. If it is absent, WorldArena reconstructs pred_world/worldlines.npz from pred_world/depth.npz, pred_world/cameras.npz, and world_gt/worldlines.npz pixel tracks before calling the evaluator.

The current sample contract sets:

  • require_full_frame_coverage = true
  • require_pred_world_artifacts = true

Success And Failure Semantics

Section titled “Success And Failure Semantics”

evaluate_generated_video(...) marks a sample as success = true only when all of the following hold:

  • inspect_physics_case(...) ends in status = ready
  • the result contains every metric named in required_core_metrics
  • frame count and frame coverage satisfy the metric contract
  • pred_world generation succeeds when require_pred_world_artifacts = true

Typical contract failures:

  • prediction frame count does not match the reference rollout
  • prediction covers only ... of the reference rollout
  • missing required core physics metrics: ...
  • predicted world artifacts are required for this physics evaluation

Those details are exposed in per_sample_scores.jsonl under:

  • report_path
  • world_gt_root
  • physics_status
  • pred_world_status
  • world_gt_status
  • metric_contract
  • missing_world_artifacts
  • missing_required_metrics when the evaluator omitted a required core metric
